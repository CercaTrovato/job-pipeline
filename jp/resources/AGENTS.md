# Job Pipeline 公开版规则

- 先读本文件、`docs/PROGRESS.md`；配置任务再读 `docs/agent-setup.md`。
- 所有个人资料和运行文件在用户工作区，不在源码中。示例只用虚构数据。
- 状态只经 `jp.db.set_status()` 推进；业务写库只在 `jp/`。适配器不分析、不写数据库。
- 大模型步骤使用可复用任务包；JD 引文、schema、需求 ID 和事实引用均须校验。
- 硬条件由规则判定；保留人工选择和跳过，不自动改写裁决。
- 不自动登录、处理验证码、发送消息或投递；风控触发即冷却。
- API 密钥只经环境变量、系统凭据库或当前会话使用，不能输出或写进配置。不能把订阅 OAuth 当 API key。
- 仅操作本项目工作区；不修改其他工具设置。配置候选先校验和测试，再原子写入，保留备份。
- 改动后验证实际行为；模拟、真实、未验证分开记录。跨系统支持需要证据。
- 经用户明确要求才提交或推送，无 AI 署名，不绕过 hooks，不 force push。
- 可以委派边界清楚的任务，写入范围不得重叠；主代理负责整合及验收。
